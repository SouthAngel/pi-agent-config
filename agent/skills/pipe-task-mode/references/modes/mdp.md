# mdp —— 写计划文件（不执行）

首词是 `mdp` 时使用本文件：交付一份**可执行的计划文件**，不是执行结果。

## 1. 做什么

读现状 → 把计划落盘 → 回报路径。**不执行计划里的任何步骤**：不改代码、不跑测试与构建。

**只读边界**：

- 允许：读文件、列目录、搜索（grep / glob）、`git log` / `git show` / `git diff`、`--help` / `--version`。
- 禁止：build / test / lint / format / codegen / install，以及任何写盘、改索引或改工作区的命令（`git status` 会刷新索引，`git add`、`git stash`、commit、checkout、reset 一律不跑）。想「先看一眼现有测试 / 构建结果」也不跑——那是执行。
- 唯一允许写的是 `docs/plans/<slug>.md`；新建 `docs/plans/` 和这一份文件属于任务范围，动手前先声明「将创建: <路径> — <用途>」。
- 请求里要求删文件、跑 git 写操作、装依赖、改仓库之外的文件时，本模式不做，也不列为已完成的步骤：写进计划步骤或「未决问题」，由用户另起一条去执行。

**上下文：只信本会话。**「现状」只能来自本会话亲手读到的文件与只读命令的输出；父 / 兄弟目录里别人的产出、别的会话留下的文件、stash 里的半成品、git 里未提交的陌生改动、README TODO、以及对「之前应该做过什么」的推测都不算依据。没核实的不补齐，在「依据」节标「未核实」。

## 2. 落盘规则

- 路径：工作区根目录 `docs/plans/<slug>.md`。
- `<slug>` **只允许小写字母、数字、连字符**。中文主题取英文 / 拼音短名；取不出就用 `plan-<yyyymmdd>-<两位序号>`（如 `plan-20261113-01`）。
- **同一主题的修订 = 覆盖同名文件**，不留旧版本，也不用 `-2` 区分版本。
- 不同主题撞了同一个 slug → 换更具体的 slug（`login` → `login-rate-limit`）；仍冲突才在文件名后加 `-2`（只用于区分不同主题，不用于区分版本）。

## 3. 文件里写什么

按如下格式：

```
# <任务名>
## 目标        <一句话>
## 范围        <改什么；明确不碰什么>
## 计划
  R1  <做什么>  判据: <怎么算完成>
  R2  ...
## 未决问题
```

- 步骤要能直接照做。
- 每条判据必须可观察。
- 计划规模不设上限：步骤多就照写，不截断、不省略。

## 4. 交接

计划文件不会被执行。要落地时，由用户另发一条带首词的消息，把文件里的 R 条目**粘进消息正文**当作清单或需求。本模式不替用户决定下一条消息用哪个首词，也不自行开始执行。

## 5. 出口与收尾

- 完成 = 文件已写并**读回逐节核对** 路径已回报：`计划文件: <路径>`。
- 写不成（读不到必要信息、给不出可执行步骤）→ `失败`。
- 需要决策的问题进「后续」，照常收尾，不停下等回话。
- **收尾格式**：状态行（`计划文件` / `失败` ）→ 一行 `未执行任何步骤` -> `要点总结`（三行以内） → `后续:`（有则写，只记文件之外发现的问题）。


## 6. 反模式

- 写完文件顺手把 R1 做了，或计划里出现「视情况」「酌情」——前者越界执行，后者不可执行。
- 把 §3 的模板当范文照抄措辞；模板只固定小节与字段。
