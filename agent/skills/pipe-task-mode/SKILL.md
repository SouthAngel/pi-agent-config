# pipe-task-mode

一次请求 = 一个**有边界的任务**。本文件**只做路由**——确定读哪份模式文件、怎么认首词。每个模式文件自包含：范围约束、验证判据、收尾状态、阻塞与失败、生命周期都在那一份里，这里不定义也不重复。

## 读取协议

**每次调用都读完整份本文件**，再读**当前模式那一份，且只读那一份**：

读取文件 ``references/modes/<前缀词>.md``

不要预先读别的模式文件：任何时候只加载一份。模式文件之间没有共享层、也不互相引用——同一模式的全部规则都在它自己那份里。

## 优先级

冲突时按此顺序取上者，不要自行调和：

1. 本文件的路由与入口限制（读哪份文件、首词怎么取）——路由与入口只按本层判
2. 模式文件的流程与格式（含该模式自己的标记与编号）
3. 模式文件里的「反模式」
4. 模式文件里的「例子」——只演示判定，**不是可抄的模板**，与上面任一层冲突时都不采信

## 入口：只有前缀词

本技能**只由首词进入**：没有「无前缀时自动选模式」这一层，也没有「按任务类型 / 复杂度选一个模式」的判据。七个词由用户首词唯一决定、互不替代：一条消息命中哪个词就只走那个模式，不得在执行中改用另一个模式，也不主动建议用户换模式。两个进入方式等价：

1. 显式命令 `/skill:pipe-task-mode nplan <请求>` / `… mdd <请求>`
2. 普通消息以模式词开头，如 `nplan 帮我改…`、`sua：按刚才的建议做`

**首词未命中时，本技能整份不参与**——包括 `/skill:pipe-task-mode` 后没跟模式词、或跟了别的词（`nfoo`、`帮我`）的情况：按普通请求正常处理，不套本文件任何流程，也不要自己挑一个模式顶上；模式文件里的范围纪律、`后续:`、阻塞判定等只在命中前缀后生效，不反向约束普通请求。

## 首词判定

**取词**：从串的第一个非空白字符开始取，到第一个空白或冒号（`:` / `：`）为止，忽略大小写。斜杠命令只取命令名之后的参数串，命令名 `/skill:pipe-task-mode` 本身不参与判定。首词后面若直接连着中文逗号等其它标点（`nplan，帮我改`），这一段整体不等于模式词，**不算命中**。

判定只发生在**两个位置**，各自从不同的串里取词：

1. **本次调用的参数串**：取第一个词 → 决定读哪一份模式文件。
2. **之后用户每条新消息的正文开头**：取第一个词 → 若命中模式词，切到那份模式文件；若未命中，视为「没换模式」，按普通正文处理（在跑的交付是否继续、旧计划怎么处理，见当前模式文件的「生命周期」节）。

**模式词不属于需求**：命中后，从参数串里去掉这个首词（连同其后的冒号），剩下的文本才是需求。正文中间再出现这些词（「这个函数叫什么 nplan」）**不触发任何切换或路由**，按普通文本处理。

**首词命中但请求为空**（只有 `nplan` 两个字）→ 按当前模式文件「生命周期」里「继续」条目说的「本会话没有可续的上下文」处理：说清缺什么，不要凭空开一份交付。
